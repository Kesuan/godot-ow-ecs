# 实验 01 · 两个英雄可以共用一个冷却系统吗？

Timothy Ford 在 GDC 2017 介绍了《守望先锋》如何用 ECS 组织玩法，以及网络模拟如何处理响应性。我们在 Godot 里先做一个小实验。玩法状态与处理逻辑分开以后，新增一组技能参数需要改哪些代码？[演讲原始资料](https://gdcvault.com/play/1024001/-Overwatch-Gameplay-Architecture-and)

## 实验设置

在同一个 World 创建三个实体。侦察员挂载 1 秒冷却，医疗兵挂载 3 秒冷却，观察者没有技能组件。一次性对三者发出施放请求，然后调用一次 `CooldownSystem.tick(world, 1.25)`。完整实验可运行 [冷却测试](../../tests/cooldown_smoke.gd)。

| 实体 | 第一次施放 | 推进 1.25 秒后 |
| --- | --- | --- |
| 侦察员 | 成功，立即重试会被拒绝 | 剩余 0 秒，可以再次施放 |
| 医疗兵 | 成功 | 剩余 1.75 秒 |
| 观察者 | 请求被拒绝 | 不在冷却系统的查询结果中 |

## 观察

新增英雄只需要创建实体并挂上带有时长的组件。系统查询的是冷却组件，因此无需知道英雄名称，也无需查找场景节点。测试直接传入时间步长，就能检查跨过归零边界的行为。

当前 World 查询时逐个检查实体，适合用来追踪这个小实验的数据流。若要研究查询成本，可以固定持有冷却组件的实体数，逐步增加观察者，测量同一查询的耗时。本实验只验证行为。
